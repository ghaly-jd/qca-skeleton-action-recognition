## Project Overview (Brief)

**What:** Hybrid quantum-classical method for skeleton action recognition. Method name: **Q-SDTW** (Quantum-estimated local Subspace Dynamic Time Warping).

**Goal:** Conference paper at IEEE QCE 2026 demonstrating Q-SDTW beats classical and deep learning baselines in the few-shot regime (K ∈ {1,2,3,5}) on three skeleton datasets.

**NOT the goal:** Beat deep learning at full-data MSR Action3D (~95-99% SOTA). Not winnable, not the target.

## Non-Negotiable Rules

These apply to every step. Read once, hold throughout.

1. **No single-seed numbers in any paper-track output.** Minimum 5 seeds, prefer 10.
2. **No notebooks in the reproduction path.** All paper numbers come from `scripts/*.py`.
3. **No hand-edited summary CSVs.** Summary CSVs are generated by `scripts/aggregate_results.py`. If a summary is wrong, the aggregator or raw CSV is wrong.
4. **No subset mode for paper numbers.** `--subset true` is only for smoke tests.
5. **No "quantum advantage" claims** without a passed Wilcoxon test backing them. SWAP gives squared overlaps; call them "quantum-estimated subspace affinity."
6. **One step per work session.** Step boundaries exist so progress is auditable. Respect them.
7. **Tests before code** for mathematical functions (overlap estimators, distances, motion features). Write the test that exposes correctness, then write the code that passes it.
8. **Read adjacent code before adding code.** If adding a baseline, read `src/distances/dtw.py` and any existing baseline first to match style and conventions.

### Step 1.5 — Implement motion features module

**Goal:** Create `src/features/motion_features.py` with all motion feature transforms.

**Why:** Position-only features leave performance on the table. Velocity captures motion direction; bone vectors are view-invariant. Phase 1.7 sweeps these to find the best.

**Action items:**

2. Add the MSR bone hierarchy to `configs/msr_action3d.yaml` under key `bone_hierarchy`. Use the standard MSR 20-joint skeleton structure (look up in the original MSR Action3D paper or in any prior skeleton-HAR paper; common reference: torso → spine → shoulders → arms, hips → legs).
3. Add a single entry-point function `apply_feature_mode(X, mode, config) -> X_transformed` that dispatches by mode name.

**Acceptance:**

- `src/features/motion_features.py` exists with all six functions plus the dispatcher.
- The dispatcher accepts mode strings and returns the right shapes:
  - `"position"` → `(T, 60)`

### Step 1.8 — Implement clean `Local-SDTW` module

**Goal:** A single clean implementation of Local Subspace DTW in `src/distances/local_sdtw.py`.

**Why:** The current Local-SDTW lives in scattered places (parts in the quantum script). Centralize it. This module is shared by the exact and SWAP variants.

**Action items:**

1. Create `src/distances/local_sdtw.py`. API:
   ```python
   def local_sdtw_distance(
       X: np.ndarray,            # (T1, D)
       Y: np.ndarray,            # (T2, D)
       window_size: int,         # frames per local window, e.g. 10
       stride: int,              # window stride, e.g. 5
       rank: int,                # subspace rank, e.g. 2
       overlap_fn: Callable[[np.ndarray, np.ndarray], float],  # returns |<u|v>|^2 or similar
   ) -> float:
       ...
   ```
2. Algorithm:
   - For X: split into local windows of `window_size` frames with `stride`. For each window, compute the centered SVD and keep top `rank` right-singular vectors as a `(D, rank)` basis. Result: a sequence of subspaces of length `M1`.
   - Same for Y → `M2` subspaces.
   - Build an `M1 × M2` cost matrix where `cost[i, j] = 1 - projection_affinity(U_i, V_j)` and `projection_affinity(U, V) = sum_{a, b} overlap_fn(U[:, a], V[:, b]) / rank`.
   - Run DTW on this cost matrix; return path-length-normalized DTW distance.
3. `overlap_fn` is a parameter. For the exact path, pass `lambda u, v: (u @ v) ** 2`. For the quantum path, pass a SWAP-test estimator. This keeps the algorithm reusable.

**Acceptance:**

- `src/distances/local_sdtw.py` exists.
- Calling with `overlap_fn = lambda u, v: (u @ v) ** 2` on two identical sequences returns ~0 distance.
- Calling on two random sequences returns a positive finite distance.

**Status update:** Mark Step 1.8 as Done.

### Step 1.16 — Profile and optimize quantum simulation

**Goal:** Make full-data quantum sweeps tractable.

**Why:** A SWAP-test full-data run at rank=3, shots=2048, 10 seeds can take days. We need it in hours.

**Action items:**

1. Profile the current `04_run_quantum_angles_sim.py` end-to-end with `cProfile` on a 20-sequence subset. Identify hot spots.
2. Apply at least these optimizations:
   - **Cache subspace bases per sequence.** Computed once, looked up per pair.
   - **Vectorize binomial sampling.** Instead of looping over shots and pairs, draw a binomial sample array of shape `(n_pairs, n_overlaps)`.
   - **Vectorize the projection affinity computation.** Use `np.einsum` for the `r × r` overlap matrix.
   - **Parallelize across seeds** using `multiprocessing.Pool`.
3. Re-profile. Document speedup in a comment at the top of `src/quantum/overlap_estimation.py`.

**Acceptance:**

- A full-data run (~280 train × 280 test) for rank=2, shots=1024, 1 seed completes in under 30 minutes on a single CPU core. (If it's already faster, document the baseline.)
